**Rama:** `feat/fase-05-modo-demo`
**Objetivo:** la app arranca, muestra *Sign in* la primera vez con **Explore demo** y **Continue as guest**, y en modo
demo navega por las 4 pestañas usando repositorios mock con datos idénticos al seed. Incluye las imágenes de
producto, el `MockStore` en memoria (pedidos, stock, ciclo de vida simulado), la inyección de repositorios y la
sesión persistida.

3. Comprueba que cada archivo pese **< 120 KB** (definición §7.5); si no, baja la calidad.

## Paso 3 · `MockStore` (`src/features/demo/data/mock-store.ts`)

Base de datos en memoria de **una sesión demo** (referencia: Agendo `mock-db.ts` + `clone.ts`). Solo lo usan los
repositorios mock.

```ts
export interface MockStoreOptions {
  latencyMs?: [number, number];   // default [300, 600]; tests use [0, 0]
  now?: () => Date;               // default () => new Date()
  lifecycleDelaysMs?: { paid: number; shipped: number; delivered: number }; // default 2000 / 8000 / 15000
}
export class MockStore {
  readonly user = DEMO_USER;
  profile: Profile;               // clone of DEMO_PROFILE
  categories: Category[];
  products: Product[];            // mutable copy: stock changes with orders
  orders: Order[];                // buildSampleOrders(now) + orders created in this session
  constructor(options?: MockStoreOptions);
  delay(): Promise<void>;                              // random latency within latencyMs
  failNext(info: DomainErrorInfo): void;               // next repository call throws it (tests)
  takeFailure(): void;                                 // throws the pending failure, if any
  onOrderChange(listener: (order: Order) => void): () => void;
  createOrder(input: StartCheckoutInput): Order;       // see rules below
  setStatus(orderId: string, status: OrderStatus): Order; // canTransition or throws DomainError conflict
  startLifecycle(orderId: string): void;               // paid -> shipped -> delivered with the delays
  recordPaymentFailure(orderId: string, reason: string): void;
  dispose(): void;                                     // clears timers and listeners
}
```

Reglas de `createOrder` (**las mismas que la RPC**, fase 04 §5.3, pero en TypeScript):
1. `validateCheckoutItems(input.items)` y `shippingAddressSchema.parse(input.shippingAddress)` → `validation`.
2. Cancela el pedido `pending_payment` previo del usuario y **restaura su stock**.
3. Productos inexistentes o inactivos → `DomainError({ code: 'productUnavailable', productIds })`.
4. Stock insuficiente → `DomainError({ code: 'outOfStock', productIds })`.
5. Descuenta stock; totales con `calculateCartTotals` + `DEFAULT_SHIPPING_POLICY`; líneas con nombre y precio congelados.
6. `shortCode` aleatorio `VT-XXXX` con el alfabeto de la fase 04; `status: 'pending_payment'`; `createdAt: now()`.
7. Notifica a los listeners.

`setStatus` rellena `paidAt`/`shippedAt`/`deliveredAt`/`canceledAt` igual que el trigger y notifica.
Todas las lecturas devuelven **copias** (`structuredClone` o un `clone` propio que preserve `Date`), para que la UI no
pueda mutar el store.

## Paso 4 · Repositorios mock

Cada uno recibe el `MockStore` en el constructor y en **cada método**: `await store.delay(); store.takeFailure();`.

| Archivo | Comportamiento |
|---|---|
| `catalog/data/mock-products.repository.ts` | `list`: filtra con `matchesFilters`, ordena con `compareProducts`, pagina por offset (`cursor`, `pageSize ?? PRODUCT_PAGE_SIZE`), `nextCursor = null` en la última página. `getById`: `notFound` (entity `product`) si no existe o inactivo. `getByIds`: solo activos. `listCategories`: por `sortOrder`. |
| `checkout/data/mock-checkout.repository.ts` | `startCheckout`: `store.createOrder` → `{ orderId, totalCents }` (sin `clientSecret`). `reportPaymentResult`: `succeeded` → `store.startLifecycle(orderId)`; `failed` → `store.recordPaymentFailure`; `canceled` → nada. |
| `orders/data/mock-orders.repository.ts` | `list`: pedidos del usuario, más recientes primero. `getById`: `notFound` (entity `order`). `subscribe`: llama a `onStatus?.('live')` de inmediato y reenvía `onOrderChange` filtrando por `orderId` si se pasa; devuelve la función de baja. |
| `auth/data/mock-auth.repository.ts` | Usuario actual = `DEMO_USER`. `sendCode` resuelve; `verifyCode` acepta `'123456'` y si no lanza `invalidCode`; `signOut` no hace nada; `onAuthChange` llama al callback con el usuario de inmediato. (En demo no se muestran pantallas de auth; sirve para tests.) |
| `account/data/mock-profile.repository.ts` | `ensureMine`/`getMine` devuelven `store.profile`; `update` lo modifica. |

Tests por repositorio (`__tests__/` junto a cada uno, con `new MockStore({ latencyMs: [0, 0] })`):
- Productos: búsqueda "mug" → 3; filtros combinados; los tres órdenes; paginación de 20 + 10 con `nextCursor`;
  `getById` inexistente → `notFound`; `failNext` hace fallar la siguiente llamada.
- Checkout: crea pedido y descuenta stock; `outOfStock` con ids; segundo checkout cancela el anterior y restaura stock;
  `reportPaymentResult('succeeded')` con **fake timers** (`jest.useFakeTimers()`) avanza `paid` (2 s), `shipped` (8 s),
  `delivered` (15 s).
- Orders: **suite de contrato** `src/test/contracts/orders-repository.contract.ts` →
  `describeOrdersRepositoryContract(name, setup)` con: `list` ordenado, `getById` + `notFound`, `subscribe` recibe cambios
  del pedido filtrado y no de otros, y deja de recibir tras `unsubscribe`. Se ejecuta contra el mock (definición §13).

export interface Repositories {

## Paso 6 · Sesión (`src/core/session/session.store.ts`)

Zustand + `persist` (AsyncStorage, `name: 'vitrina-session'`, `version: 1`), persistiendo solo `hasSeenWelcome` e `isDemo`:

```ts
interface SessionState {
  hasSeenWelcome: boolean;
  isDemo: boolean;
  demoSessionId: number;      // not persisted; bump = fresh MockStore
  markWelcomeSeen(): void;
  enterDemo(): void;          // isDemo = true, hasSeenWelcome = true, demoSessionId++, queryClient.clear()
  exitDemo(): void;           // no-op if isDemoForced; else isDemo = false, queryClient.clear()
}
export const useIsDemo = () => useSessionStore((s) => isDemoForced || s.isDemo);
```

- `isDemoForced` viene de `env.ts` (fase 01). Si es `true`, la app **siempre** está en demo, no muestra *Sign in* al
  arrancar y oculta "Exit demo".
- Vaciar el carrito al entrar/salir del demo (F2 CA3) se hace en el hook de presentación `useDemoActions()`
  (`src/features/demo/presentation/hooks/use-demo-actions.ts`), que llama a `enterDemo`/`exitDemo`; la fase 07 le añade
  `clearCart()`. Así `core/` no depende del carrito.
- `useSessionMode()` en `src/features/auth/presentation/hooks/use-session-mode.ts`: devuelve `'demo'` si `useIsDemo()`,
  si no `'guest'`. La fase 08 añade `'live'` cuando hay sesión.
- Tests: `enterDemo` cambia `isDemo`, incrementa `demoSessionId` y vacía la caché de Query; `exitDemo` con demo forzado
  no hace nada; solo `hasSeenWelcome` e `isDemo` se persisten.
